# 사회적 출발선 — 체험 활동 웹앱 (WebRTC 버전)

중학교 도덕 수업용 "사회적 출발선 차이 체험 활동" 웹앱입니다.
**어떤 외부 서비스에도 가입하지 않고**, GitHub Pages(정적 파일 호스팅)만으로 동작합니다.

---

## 1. 어떻게 서버 없이 동작하나요?

이 앱은 **WebRTC**라는 브라우저 표준 기술을 사용합니다. 교사의 브라우저가 곧 "서버(호스트)"
역할을 하고, 학생들의 브라우저가 거기에 직접 연결됩니다. 데이터는 어떤 회사의 데이터베이스에도
저장되지 않고, **교사 기기의 브라우저(localStorage)에만** 저장됩니다.

두 브라우저가 처음 서로를 찾을 때만 "PeerJS"라는 오픈소스 라이브러리가 제공하는 무료 공개
중계 서버(`0.peerjs.com`)를 잠깐 거칩니다. 이 중계 서버는 **가입도, API 키 발급도 필요 없고**,
연결을 이어주는 역할만 할 뿐 실제 데이터(학번, 조건, 이동 결과)는 이 서버를 거치지 않고
교사 ↔ 학생 브라우저 사이를 직접 오갑니다.

### 알아두어야 할 점 (트레이드오프)
- 이 공개 중계 서버는 무료 커뮤니티 서비스라 **가끔 불안정할 수 있습니다.** 상업적 안정성
  보장이 없습니다.
- **학교 와이파이가 기기 간 직접 통신(WebRTC)을 막아두면 연결이 안 될 수 있습니다.**
  특히 보안을 위해 "클라이언트 격리"를 켜둔 학교망에서는 실패할 가능성이 있습니다.
  수업 전에 실제 학교 와이파이 환경에서 한 번 테스트해보시길 권장합니다.
- **방 데이터는 교사의 그 브라우저·그 기기에만 저장됩니다.** 즉:
  - 교사가 페이지를 새로고침해도 같은 기기·같은 브라우저라면 [방 이어서 진행하기]로 복구됩니다.
  - 하지만 **다른 기기나 다른 브라우저에서는 같은 방을 이어받을 수 없습니다.**
  - 교사가 활동 도중 새로고침하면, 잠깐 연결이 끊겼다가 학생들의 화면이 자동으로 재연결을
    시도합니다(별도 조작 불필요). 재연결에는 몇 초 정도 걸릴 수 있습니다.

## 2. 전체 구조

```
social-starting-line/
├── index.html          ← 첫 화면 (교사/학생 선택)
├── teacher.html         ← 교사 화면 (호스트 역할)
├── student.html         ← 학생 화면
├── css/style.css
├── js/
│   ├── common.js         (공통 로직 + 기본 예시 데이터 + 엑셀 파싱)
│   ├── teacher.js         (WebRTC 호스트 로직)
│   └── student.js         (WebRTC 클라이언트 로직 + 자동 재연결)
└── sample-config.xlsx    ← 조건/질문 편집용 엑셀 템플릿
```

가입이나 키 설정이 필요한 파일이 없습니다. **폴더를 그대로 GitHub 저장소에 올리기만 하면 됩니다.**

---

## 3. GitHub Pages로 배포하기

1. GitHub에 새 저장소를 만들고, 이 폴더 안의 파일들을 모두 업로드합니다.
2. 저장소 **[Settings] → [Pages]** 이동
3. **Source**를 `Deploy from a branch`로, 브랜치는 `main`(또는 `master`), 폴더는 `/ (root)`로 설정 후 저장
4. 1~2분 후 `https://<계정이름>.github.io/<저장소이름>/` 주소로 접속하면 첫 화면이 나타납니다.

## 4. 수업 당일 사용 순서

### 교사
1. `.../teacher.html` 접속 → **[방 만들기]** 클릭 → 4자리 방 번호 확인 → 학생들에게 공지
2. (선택) 조건/질문을 바꾸고 싶다면 엑셀 파일 업로드 — 5번 참고. 업로드하지 않으면 기본 예시로 진행됩니다.
3. 학생들이 입장하는 대로 화면에 실시간으로 표시됩니다.
4. 모두 입장했으면 **[모든 학생 입장 확인 → 활동 시작]** 클릭
   → 학생 전원에게 무작위 조건이 배정되고, 모두 출발선(0칸)에서 시작합니다.
5. 질문이 표시됩니다. 학생들이 이동을 마치면 트랙 위 아이콘이 실시간으로 움직이고,
   아이콘에 마우스를 올리면 학번과 조건이 보이며, "아직 응답하지 않음" 목록도 실시간 갱신됩니다.
6. **[다음 질문으로]** 로 진행, 마지막 질문 후에는 **[활동 종료하기]**.
7. 활동 종료 후 학생별 최종 위치가 정리되어 표시됩니다.
8. **브라우저를 새로고침한 경우**: [이미 만든 방에 다시 들어가기]에 같은 방 번호를 입력하면
   (같은 기기·브라우저에 한해) 진행 상황이 그대로 복구되고, 학생들도 자동으로 재연결됩니다.

### 학생
1. `.../student.html` 접속 → 방 번호, 학번 입력 → **[입장하기]**
2. 활동이 시작되면 배정된 조건이 화면 위쪽에 항상 표시됩니다.
3. 질문을 읽고 **[해당함]** 또는 **[해당 없음]** 중 하나를 선택합니다. (질문당 1회만 가능)
4. 새로고침하거나 일시적으로 연결이 끊겨도, 앱이 자동으로 선생님 화면에 재연결을 시도하며
   지금까지의 위치·조건·응답 기록은 그대로 유지됩니다. (단, 선생님이 방을 계속 열어두고 있어야 합니다)

## 5. 조건 / 질문을 엑셀로 편집하기 (코딩 지식 불필요)

동봉된 `sample-config.xlsx` 파일을 열어서 수정한 뒤, 교사 화면의 **"조건 · 질문 설정"**에서
업로드하면 됩니다. (반드시 **활동 시작 전**에 업로드하세요.)

### `conditions` 시트
| 항목 | 선택지 |
|---|---|
| 나이 | 13세,14세,15세 |

- 행을 추가/삭제해서 조건 항목 개수를 자유롭게 조정
- "선택지"는 쉼표(,)로 구분 — 그중 하나가 학생에게 무작위 배정됩니다

### `questions` 시트
| 순서 | 질문내용 | 뒤로버튼텍스트 | 뒤로칸수 | 앞으로버튼텍스트 | 앞으로칸수 |
|---|---|---|---|---|---|
| 1 | 어쩔 수 없이 1~2년 단위로 이사를 다녀야 한다면 | 해당함 → 뒤로 | -1 | 해당 없음 | 0 |

- **뒤로칸수/앞으로칸수**: 음수 = 뒤로, 양수 = 앞으로, 0 = 이동 없음. 질문마다 자유롭게 설정 가능
- 행을 추가/삭제해서 질문 개수를 자유롭게 조정

시트 이름(`conditions`, `questions`)은 그대로 유지해주세요.

## 6. 자주 묻는 질문

**Q. 학생이 여러 명 한꺼번에 접속해도 되나요?**
네. 각 학생의 브라우저가 교사 브라우저와 개별적으로 직접 연결되므로, 학급 인원(30명 내외)
정도는 문제없이 처리됩니다.

**Q. 학교 와이파이에서 연결이 안 되면 어떻게 하나요?**
학생 기기를 개인 모바일 데이터로 전환해서 접속해보세요. 또는 학교 네트워크 관리자에게
WebRTC(UDP) 트래픽이 차단되어 있는지 문의해볼 수 있습니다.

**Q. 교사가 실수로 탭을 완전히 닫아버리면요?**
같은 기기의 같은 브라우저에서 `teacher.html`을 다시 열고 [방 이어서 진행하기]에 같은
방 번호를 입력하면 저장된 상태(학생 목록, 조건, 위치, 응답 기록)가 그대로 복원됩니다.
연결이 끊겼던 학생들도 자동으로 다시 연결을 시도합니다.

**Q. 데이터는 언제 사라지나요?**
교사 기기의 브라우저 저장공간(localStorage)에 남아 있으며, 브라우저 방문 기록/사이트 데이터를
삭제하면 함께 삭제됩니다. 외부 서버에는 애초에 저장되지 않습니다.

**Q. 같은 질문에 학생이 두 번 응답할 수 있나요?**
아니요. 한 번 응답하면 버튼이 비활성화되고, 재접속해도 이미 응답한 상태로 표시됩니다.
