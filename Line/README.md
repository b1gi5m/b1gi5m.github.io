# 사회적 출발선 — 체험 활동 웹앱 (WebRTC 버전)

중학교 도덕 수업용 "사회적 출발선 차이 체험 활동" 웹앱입니다.
어떤 외부 서비스에도 가입하지 않고, GitHub Pages(정적 파일 호스팅)만으로 동작합니다.

---

## 1. 어떻게 서버 없이 동작하나요?

교사의 브라우저가 "호스트" 역할을 하고, 학생들의 브라우저가 WebRTC로 거기에 직접 연결됩니다.
데이터는 어떤 회사의 데이터베이스에도 저장되지 않고, **교사 기기의 브라우저(localStorage)에만**
저장됩니다. 처음 연결을 맺을 때만 PeerJS의 무료 공개 중계 서버(`0.peerjs.com`)를 잠깐 거치는데,
가입도 API 키도 필요 없고, 실제 데이터는 이 서버를 거치지 않습니다.

### 알아두어야 할 점
- 무료 공개 중계 서버라 가끔 불안정할 수 있습니다.
- 학교 와이파이가 기기 간 직접 통신(WebRTC)을 막아두면 연결이 안 될 수 있으니, 수업 전
  실제 네트워크에서 한 번 확인해보시길 권장합니다.
- 방 데이터는 **교사의 그 브라우저·그 기기에만** 저장됩니다. 다른 기기/브라우저에서는
  같은 방을 이어받을 수 없습니다.
- 교사가 새로고침해도 [방 이어서 진행하기]로 복구되고, 연결이 끊겼던 학생들도 자동 재연결됩니다.

## 2. 전체 구조

```
social-starting-line/
├── index.html          ← 첫 화면 (교사/학생 선택)
├── teacher.html         ← 교사 화면 (호스트)
├── student.html         ← 학생 화면
├── css/style.css
├── js/
│   ├── common.js         (공통 로직 + 기본 예시 데이터 + 엑셀 파싱)
│   ├── teacher.js
│   └── student.js
└── config.xlsx          ← 조건/질문 설정 파일 (여기를 수정해서 사용)
```

---

## 3. GitHub Pages로 배포하기

1. GitHub에 새 저장소를 만들고, 이 폴더 안의 파일들을 모두 업로드합니다.
2. 저장소 **[Settings] → [Pages]** 이동
3. **Source**를 `Deploy from a branch`로, 브랜치는 `main`(또는 `master`), 폴더는 `/ (root)`로 설정 후 저장
4. 1~2분 후 `https://<계정이름>.github.io/<저장소이름>/` 주소로 접속하면 첫 화면이 나타납니다.

## 4. 조건 / 질문 수정하기 (코딩 지식 불필요)

교사가 **[방 만들기]**를 누르는 순간, 같은 폴더의 **`config.xlsx`** 파일을 자동으로 읽어서
조건과 질문을 불러옵니다. 앱 안에는 업로드 버튼이 없습니다 — 대신 이렇게 하시면 됩니다.

1. `config.xlsx` 파일을 내려받아 엑셀에서 엽니다.
2. `conditions` 시트와 `questions` 시트의 내용을 원하는 대로 수정합니다.
3. 저장한 뒤, GitHub 저장소의 **같은 위치(루트 폴더)에 `config.xlsx`라는 같은 이름으로**
   다시 업로드해서 기존 파일을 덮어씁니다.
4. 새로고침 없이도, 다음에 [방 만들기]를 누르는 순간부터 새 설정이 적용됩니다.

파일이 없거나 형식을 읽을 수 없으면 기본 예시 데이터로 자동 대체됩니다.

### `conditions` 시트
| 항목 | 선택지 |
|---|---|
| 나이 | 13세,14세,15세 |

- 행 추가/삭제로 조건 항목 개수 조정, "선택지"는 쉼표(,)로 구분 — 그중 하나가 무작위 배정됩니다.

### `questions` 시트
| 순서 | 질문내용 | 뒤로버튼텍스트 | 뒤로칸수 | 앞으로버튼텍스트 | 앞으로칸수 |
|---|---|---|---|---|---|
| 1 | 어쩔 수 없이 1~2년 단위로 이사를 다녀야 한다면 | 해당함 | -1 | 해당 없음 | 0 |

- 칸수는 음수(뒤로)/양수(앞으로)/0(이동없음) 모두 가능, 질문마다 자유롭게 설정.
- 행을 추가/삭제해서 질문 개수를 자유롭게 조정. 시트 이름(`conditions`, `questions`)은 그대로 유지해주세요.
- **중요**: "뒤로버튼텍스트"/"앞으로버튼텍스트"는 학생 화면에 그대로 노출됩니다. 학생이 자신의
  이동 방향을 눈치채지 못하도록, **"뒤로"/"앞으로" 같은 방향을 암시하는 표현은 넣지 말고**
  "해당함" / "해당 없음"처럼 중립적으로 작성하는 것을 권장합니다.

## 5. 수업 당일 사용 순서

### 교사
1. `teacher.html` 접속 → **[방 만들기]** → 4자리 방 번호를 학생들에게 공지
2. 학생들이 입장하는 대로 목록에 표시됩니다 → 모두 입장했으면 **[활동 시작]**
   → 학생 전원에게 무작위 조건이 배정되고, 모두 출발선(가운데 선)에서 시작합니다.
3. 질문이 표시되면, 학생들이 이동을 마치는 대로 화면 위쪽의 트랙에서 아이콘이 위(앞으로)/
   아래(뒤로)로 실시간 이동합니다. 아이콘은 평소엔 학번이 보이지 않고, **마우스를 올려야만**
   학번과 배정된 조건이 보입니다.
4. 아래쪽 패널에서 "미응답 / 응답 완료" 학생을 바로 확인하고, 같은 자리에서 **[다음 질문으로]**
   또는 **[활동 종료]**를 선택할 수 있습니다. 질문을 다 마치지 않아도 원하는 시점에 종료할 수
   있습니다.
5. 종료 화면에서는 다른 정보 없이 수평선 기준 학생들의 최종 위치만 보이고, 역시 마우스를
   올려야 학번·조건이 보입니다.
6. 수업이 완전히 끝났으면 **[이 방 삭제하기]**를 누르세요. 접속해 있던 학생들은 즉시 초기
   화면으로 돌아가고, 나중에 새로고침해도 예전 방으로 돌아가지 않습니다.

### 학생
1. `student.html` 접속 → 방 번호, 학번(4자리) 입력 → **[입장하기]**
2. 활동이 시작되면 먼저 **자신에게 배정된 조건을 보여주는 화면**이 뜹니다. 충분히 읽고
   [확인했습니다 · 질문 보러가기]를 눌러야 다음 화면(질문)으로 넘어갑니다. (질문마다 반복되지
   않고, 활동 시작 시 한 번만 표시됩니다)
3. 질문 화면에서는 질문과 두 개의 선택지만 크게 보이고, 조건표는 작은 [내 조건 다시 보기]
   버튼을 눌러야 확인할 수 있습니다 — 질문에 집중할 수 있도록 한 것입니다.
4. 선택지 중 하나를 고르면 바로 제출되지 않고 "선택된 상태"로 표시되며, **[확정하기]** 버튼을
   눌러야 최종 제출됩니다. (실수로 잘못 누르는 것을 방지) 선택지 자체에는 어느 쪽이 앞으로,
   어느 쪽이 뒤로 이동하는지 표시되지 않습니다.
5. 새로고침하거나 일시적으로 연결이 끊겨도 자동으로 재연결을 시도하며 진행 상황이 유지됩니다.
   (단, 재연결되면 조건 확인 화면이 한 번 더 나타날 수 있습니다)
6. 선생님이 방을 삭제하면 자동으로 초기 화면으로 돌아갑니다.

## 6. 자주 묻는 질문

**Q. 학생이 여러 명 한꺼번에 접속해도 되나요?**
네. 각 학생의 브라우저가 교사 브라우저와 개별적으로 직접 연결되므로 학급 인원 정도는 문제없습니다.

**Q. 학교 와이파이에서 연결이 안 되면?**
학생 기기를 개인 모바일 데이터로 전환해보세요. 또는 사전에 학교 네트워크에서 테스트해보세요.

**Q. 교사가 탭을 완전히 닫아버리면?**
같은 기기·같은 브라우저에서 `teacher.html`을 다시 열고 [방 이어서 진행하기]에 같은 방 번호를
입력하면 저장된 상태가 복원되고, 학생들도 자동 재연결됩니다.

**Q. 활동을 완전히 끝낸 뒤 데이터는요?**
종료 화면의 [이 방 삭제하기]를 누르면 교사 기기에 저장된 데이터가 삭제되고, 학생들도 초기
화면으로 이동합니다.
